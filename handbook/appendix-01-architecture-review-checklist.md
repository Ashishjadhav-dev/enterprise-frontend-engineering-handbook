# Appendix 1: Architecture Review Checklist

Reusable reference for project delivery, reviews and engineering governance.

- Business capability and owner are clear
- Module boundary is explicit
- Rendering strategy is documented
- Data ownership is defined
- Failure modes are handled
- Security boundary is server-enforced
- Performance impact is measured
- Migration and rollback are documented

## Usage

Copy this checklist into an issue, pull request, architecture review, or team runbook. Add an owner and evidence for every completed item.
