# Appendix 18: Strict TypeScript Migration Plan

Reusable reference for project delivery, reviews and engineering governance.

- Capture unsafe baseline
- Enable strict rules in new modules
- Validate API boundaries
- Replace broad any types
- Use expect-error with expiry only when necessary
- Add no-growth CI rule
- Migrate high-change modules first
- Remove temporary compatibility types

## Usage

Copy this checklist into an issue, pull request, architecture review, or team runbook. Add an owner and evidence for every completed item.
